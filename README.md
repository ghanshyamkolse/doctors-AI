# AI Clinical Scribe

AI-powered clinical scribe and voice assistant backend for doctors. It accepts consultation audio
or raw transcripts, extracts structured SOAP notes and prescriptions, and stores the clinical
encounter.

> **Status:** development scaffold. AI extraction and speech-to-text are deterministic mocks.
> This software is not a medical device and must not be used for clinical decisions without
> clinician review, validation, and the appropriate regulatory clearances.

## Features

- Patient management (create, read, update, delete).
- Consultation ingestion from a raw transcript.
- Automatic SOAP-note and medication extraction through a provider-agnostic
  `LLMExtractionService` boundary.
- Prescription items persisted one-to-many with consultations.
- Clinician editing and re-processing of previously stored transcripts.
- Mock Whisper-compatible audio transcription endpoint.
- Strict JSON response envelope (`status`, `message`, `data`, `timestamp`).
- Jakarta Bean Validation with structured field-level error payloads.
- PostgreSQL + JPA, OpenAPI/Swagger UI, Actuator health/info.
- Unit and integration tests.

## Prerequisites

- JDK 25 or newer (`java -version`)
- Maven 3.9+ (`mvn -version`) or the included Maven Wrapper (`./mvnw` / `.\mvnw.cmd`)
- PostgreSQL 16 running locally, or Docker for the provided compose file

Ensure `JAVA_HOME` points to a valid JDK. On Windows:

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-25"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

## Quick Start

### 1. Start PostgreSQL

```bash
docker compose up -d
```

This creates database `ai_clinical_scribe` with user `scribe` / password `scribe` on port `5432`.
To use an existing PostgreSQL instance instead, set `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD`.

### 2. Run the application

```bash
./mvnw spring-boot:run
```

On Windows PowerShell:

```powershell
.\mvnw.cmd spring-boot:run
```

The API starts on `http://localhost:8080`.

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>
- Health: <http://localhost:8080/actuator/health>

### 3. Build and run the jar

```bash
./mvnw clean package
java -jar target/ai-clinical-scribe-0.1.0-SNAPSHOT.jar
```

Skip tests while packaging with `./mvnw clean package -DskipTests`.

## Configuration

All settings have development defaults; override them with environment variables.

| Variable | Default | Description |
| --- | --- | --- |
| `DB_URL` | `jdbc:postgresql://localhost:5432/ai_clinical_scribe` | JDBC URL |
| `DB_USERNAME` | `scribe` | Database user |
| `DB_PASSWORD` | `scribe` | Database password |
| `DB_POOL_SIZE` | `10` | Hikari maximum pool size |
| `JPA_DDL_AUTO` | `update` | Hibernate schema mode; use `validate` with migrations in production |
| `JPA_SHOW_SQL` | `false` | Log SQL statements |
| `SERVER_PORT` | `8080` | HTTP port |
| `AI_PROVIDER` | `mock` | LLM adapter selector |
| `AI_MODEL` | `mock-soap-extractor-v1` | Model label reported by the mock |
| `WHISPER_PROVIDER` | `mock` | Speech-to-text adapter selector |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:3000,http://localhost:5173` | Comma-separated origins |
| `LOG_LEVEL` | `INFO` | Log level for `com.scribe` |

In production, never rely on the default database credentials.

## API Overview

Base path: `/api/v1`. All responses use:

```json
{
  "status": "SUCCESS",
  "message": "Consultation processed and saved successfully",
  "data": {},
  "timestamp": "2026-10-23T10:15:31Z"
}
```

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/patients` | Create a patient |
| `GET` | `/patients` | List patients |
| `GET` | `/patients/{id}` | Get a patient |
| `PUT` | `/patients/{id}` | Update a patient |
| `DELETE` | `/patients/{id}` | Delete a patient without consultations |
| `POST` | `/consultations` | Extract and persist a consultation |
| `GET` | `/consultations?patientId={id}` | List consultations (optional patient filter) |
| `GET` | `/consultations/{id}` | Get a consultation with SOAP note and prescriptions |
| `PUT` | `/consultations/{id}` | Apply clinician edits / replace prescriptions |
| `POST` | `/consultations/{id}/reprocess` | Re-run extraction on the stored transcript |
| `DELETE` | `/consultations/{id}` | Delete a consultation |
| `POST` | `/transcriptions` | Upload audio (multipart `audio`) and receive a transcript |

### End-to-end example

Create a patient:

```bash
curl -X POST http://localhost:8080/api/v1/patients \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Jane Doe",
    "age": 34,
    "gender": "FEMALE",
    "contactNumber": "+1 555 0100",
    "medicalHistory": "No known drug allergies"
  }'
```

Extract a consultation (use the patient `id` returned above):

```bash
curl -X POST http://localhost:8080/api/v1/consultations \
  -H "Content-Type: application/json" \
  -d '{
    "patientId": 1,
    "rawTranscript": "Patient reports a sore throat and fever for three days. The temperature is 38.4 C and the throat is red. It looks like acute pharyngitis. I will prescribe amoxicillin 500 mg three times daily for 7 days. Follow up in one week."
  }'
```

Abbreviated response:

```json
{
  "status": "SUCCESS",
  "message": "Consultation processed and saved successfully",
  "data": {
    "id": 1,
    "patientId": 1,
    "soapNote": {
      "subjective": "Patient reports a sore throat and fever for three days.",
      "objective": "The temperature is 38.4 C and the throat is red.",
      "assessment": "It looks like acute pharyngitis.",
      "plan": "I will prescribe amoxicillin 500 mg three times daily for 7 days. Follow up in one week."
    },
    "prescriptionItems": [
      {
        "id": 1,
        "consultationId": 1,
        "medicineName": "amoxicillin",
        "dosage": "500 mg",
        "frequency": "three times daily",
        "duration": "7 days"
      }
    ],
    "createdAt": "2026-10-23T10:15:30Z"
  },
  "timestamp": "2026-10-23T10:15:31Z"
}
```

Upload audio (mock transcription):

```bash
curl -X POST http://localhost:8080/api/v1/transcriptions \
  -F "audio=@consultation.mp3"
```

The mock returns a canned clinical dialogue. Submit `data.transcript` to
`POST /api/v1/consultations` to complete the voice-to-SOAP flow.

### Validation errors

Missing or invalid fields return `400` with the same envelope:

```json
{
  "status": "ERROR",
  "message": "Request validation failed",
  "data": {
    "code": "VALIDATION_FAILED",
    "violations": [
      { "field": "name", "message": "name is required" },
      { "field": "age", "message": "age must be greater than or equal to 0" }
    ]
  },
  "timestamp": "2026-10-23T10:15:31Z"
}
```

### Notes on the mock AI layer

`MockLlmExtractionService` splits the transcript into sentences, classifies them into
subjective/objective/assessment/plan sections using clinical keywords, and extracts prescriptions
with a deterministic pattern such as:

```
prescribe amoxicillin 500 mg three times daily for 7 days
```

This is intentionally simple. It exists to make the full pipeline runnable and testable. Replace it
by implementing `LLMExtractionService` and activating the adapter with `AI_PROVIDER`.

## Testing

The test profile uses an in-memory H2 database in PostgreSQL compatibility mode, so no external
services are required.

```bash
./mvnw test
```

On Windows PowerShell: `.\mvnw.cmd test`.

Covered:

- SOAP and medication extraction heuristics.
- Consultation service orchestration and patient-existence checks.
- REST integration tests for patient creation, consultation generation, and validation errors.
- Spring context startup.

## Database Notes

- JPA schema generation is enabled for development (`JPA_DDL_AUTO=update`).
- Production should use Flyway or Liquibase migrations and `JPA_DDL_AUTO=validate`.
- Prescription items are deleted with their consultation (`orphanRemoval`, cascade).
- Patients with existing consultations cannot be deleted.
- The reference SQL and production migration notes are in
  [implementation_plan.md](implementation_plan.md#4-database-schema).

## Troubleshooting

**`mvn` reports that `JAVA_HOME` is not defined correctly**

Point `JAVA_HOME` at a JDK root that contains `bin/java.exe`, then open a new terminal. Verify with
`mvn -version`.

**Application cannot connect to PostgreSQL**

Check that PostgreSQL is running, the database exists, and `DB_URL`/`DB_USERNAME`/`DB_PASSWORD`
match. With Docker, run `docker compose ps` and wait for the health check to pass.

**Port 8080 is already in use**

Set `SERVER_PORT` to another port.
